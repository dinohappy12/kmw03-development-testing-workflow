# ChatGPT 模式、工具與工作續接

## 啟動時先給模式建議
新開案或工作性質明顯改變時，先用三到五行交代：本次任務、建議選項、理由、較省的替代、何時值得升級。不要每個微小步驟都重複推薦。已知足夠就繼續可做的盤點，無須先等使用者再次批准。

先辨認使用者在一般 ChatGPT 對話、Work 或 Codex；只有模式選擇真的影響後續時才問。能查到當前選單就依選單；查不到時以條件式說明，不聲稱看過使用者介面。型號可能改版，下面是 2026-10-28 的官方文件快照，未來使用前需核對。

| 工作 | Work／Codex 可選時的起點 | 一般 ChatGPT 對話 |
|---|---|---|
| 明確單檔修正、整理資料 | GPT-6 Luna＋Low | Instant；複雜判斷再升級 |
| 跨檔開發、測試、整合 | GPT-6.1 Sol＋Medium | Thinking 的 Medium／標準選項，以帳號實際名稱為準 |
| 證據衝突、難定位根因、架構抉擇 | 先縮小重現；需要時建議 Sol 更高思考強度 | 視帳號選 High／Extra High；說明要解決哪個卡點 |
| 純跑固定測試 | 沿用目前模型，交程式執行 | 必須有實際執行工具；換聰明模型不能補足工具 |

不要把 Luna、Sol、Astra 與 ChatGPT 各思考按鈕當成永遠一對一的關係。免費／付費／工作區可用項目不同。若使用者看不到推薦選項，只需提供實際可選項目再對照。Astra／Pro 僅於高難度任務值得時建議，不是預設。建議是成本與能力的取捨，沒有實測不可承諾省多少 token。

範例：
> 本次是跨檔技能升級，建議選 GPT-6.1 Sol＋Medium；若你在一般 ChatGPT，就選帳號提供的 Thinking 標準／Medium。先用程式做固定檢查，只有根因仍不清楚才建議提高思考強度。模型由你手動切換，我不能替你改這段對話的設定。

## 先確認能實際做什麼
用已提供的工具判斷，不為證明權限亂寫資料。簡短列可做／待補：來源讀取、檔案編輯、命令執行、瀏覽器、GitHub 寫入、Plugin Creator、Notion。只查本次需要的能力。

- 只有對話：可整理規格、提出案例、審查已貼內容；沒有執行結果就標「未執行」。
- 有檔案與命令：可跑本機測試；無登入仍不能當帳號操作。
- 有相應連接工具及授權：才可寫 GitHub／Notion 或更新 Plugin；寫入後還要回讀。
- Skill 是方法，不會自行增加工具、權限、費用額度、背景執行或模型切換能力。
- 提到另一支 Skill 的名稱，不等於已載入。目標環境有正式呼叫工具才用工具；沒有就讀本包對應方法。外部技能明訂僅限人手啟動時，提示使用者啟動，不能假裝自動呼叫。不要求 ChatGPT 安裝 Claude 專用 setup 或使用不存在的 slash 指令。

## 跨輪續接
任務長到可能換對話時，在專案測試／工作記錄留一份簡短 Markdown：

- 正式主檔與本輪範圍；已確認／待確認決策。
- 任務編號、前置任務、交付與驗收條件、待做／進行中／受阻／待驗收／完成。
- 每項的實際證據與未測範圍；沒有證據不能把「已寫程式」當「完成」。
- 原測試計畫、state、report 路徑及剩餘預算；換對話不重置。
- 下一個可以開始的最小任務、卡點與需要誰提供什麼。

先回讀上述資料再接續，避免重新探索與遺失決策。純 Markdown 即可，不強迫學員建立資料庫或 JSON。私人資料留在私人工作副本。
